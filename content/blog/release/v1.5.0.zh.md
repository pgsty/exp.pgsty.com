PG Exporter v1.5.0 升级 Go 工具链与依赖，修正复制采集器的身份与状态映射，并修复目标 URL、自动发现、健康检查、采集计划、时间配置和 HTTP 路由六类运行时缺陷。

默认配置仍包含 **58 个 YAML 文件、96 个采集器分支、59 个命名空间、460 个不同指标定义**。指标数量跨全部版本分支去重，包含默认关闭的采集器和两个尚未展开的 SQL 直方图；它不表示每次抓取都会输出 460 条时序。

## 变更摘要

- **连接 URL 更安全：** URL 语法、查询参数转义或解码后的参数名非法时，启动立即失败，诊断不再暴露原始连接串。规范化错误参数时，不会再静默丢弃显式 TLS 选项。选中的 `PG_EXPORTER_URL_FILE` 为空或仅含空白时也会拒绝启动。
- **自动发现连接正确数据库：** 数据库身份复用 `lib/pq` 解析，包括 `dbname` 与 `database` 别名。替换发现数据库的路径时清除冲突参数，保留库名特殊字符，避免多个连接重复采集同一库、产生重复指标并使 HTTP 返回 500。
- **健康响应保持一致：** 每次响应从一个原子状态快照生成 HTTP 状态码和正文，避免并发探测、抓取与重载时出现 HTTP 200 搭配 `down` 或 `starting`。健康检查仍使用目标状态缓存。
- **采集计划跟随元数据：** 元数据预检成功后，连接用户、Schema 集合或扩展集合变化会使计划失效。下一次抓取选中新增的合格采集器；依赖移除后不再选中相应采集器。集合不变时保留缓存。
- **拒绝非法时间配置：** YAML TTL、timeout 与谓词 TTL 拒绝 NaN、无穷大和导致正向时长溢出的值；零值、默认值及有限负超时关闭期限的语义不变。
- **保证指标路径可达：** 启动时检查当前 HTTP mux 实际选择的指标处理器，覆盖解码路径与重定向，避免校验成功但请求进入首页或重定向。
- **修正复制身份与状态：** 全部 `pg_sub_*` 样本增加 `datname` 标签，区分不同数据库中的同名订阅。`pg_recv_state` 改用真实接收器状态字典，legacy 查询改用 PG9.6 兼容的 `substring()`。
- **校准采集器描述：** 明确可选复制 origin 的权限要求、发布端表数量与订阅端表／序列数量的区别，并将 `pg_backend` 的说明修正为按后端类型分组。这些说明修改不新增指标族，也不启用可选采集器。

## 指标、仪表盘与告警兼容性 {#metric-compatibility}

与同一 PostgreSQL 版本上的 v1.4.1 相比，**v1.5.0 没有新增、删除或改名内置 SQL 指标**。类型和单位不变，但标签与状态映射有变化。PostgreSQL 19 支持最早随 [v1.3.0](/zh/release/v1.3.0/) 发布；升级数据库还可能改变所选 SQL 分支与指标含义。

| 变化来源 | 指标 | 兼容性处理 |
|:---|:---|:---|
| v1.5.0 配置 | `pg_sub_*` | 每条样本增加 `datname`。连接与聚合时保留数据库和订阅身份；新标签集会产生新时序。 |
| v1.5.0 配置 | `pg_recv_state` | 真实接收器状态 `starting`、`waiting`、`restarting`、`stopped` 从 `-1` 改为 6–9。更新值映射和状态告警；编码 1–3 保留。 |
| PG18 → PG19 | PG18 已有的指标名 | 本配置的 PG19 分支没有删除或改名这些指标；这不保证 PostgreSQL 自身提供的语义和标签取值不变。 |
| PG19 | `pg_sub_sync_error_count` | 名称保留，值变为表与序列同步错误之和。只监控表同步时用 `pg_sub_sync_table_error_count`，序列分量由 `pg_sub_sync_seq_error_count` 提供。不要把分量和总和重复相加。 |
| PG19 | `pg_sub_has_worker`、`pg_sub_reset_time`、`pg_sub_confl_*` | 新增 worker 存在标记、重置时间与八个冲突计数器。没有 apply worker 时仍可能保留订阅行，不能仅凭指标存在判断 worker 健康。 |
| PG19 | `pg_subrel_count` | 同时包含表和序列；`pg_pubrel_count` 仍只统计表。检查面板名称与数量比较规则。 |
| PG19 | `pg_wal_fpi_bytes`、`pg_lock_stat_*`、`pg_recovery_state_*`、`pg_vacuum_score_*` | 属于新增指标。恢复状态仅用于备库，自动清理评分仅用于主库；原有 WAL、锁分布和恢复指标族保留。 |
{.full-width .wide .expand}

从 PG17 或更早版本升级的用户还需迁移旧名：检查点指标自 PG17 起移出 `pg_bgwriter_*`，而 `pg_wal_write`、`pg_wal_sync`、`pg_wal_write_time`、`pg_wal_sync_time` 自 PG18 起不再输出。[完整兼容性指南](/zh/compatibility/#older-postgresql-metrics)逐项列出替代指标、标签／聚合差异与混合版本 PromQL。

部署前应执行实际仪表盘和告警表达式，并测试时序缺失的情况。抓取成功不代表所有预期指标都存在；告警表达式返回空结果时可能静默失效。[缺失指标检查](/zh/compatibility/#missing-metric-alerts)提供逐目标规则，并说明哪些缺失属于正常情况。[PG19 指标对照表](/zh/compatibility/#postgresql-19-metrics)链接到发布标签中的精确定义；PostgreSQL 验证范围仍为 19 RC1。

## 升级提示

1. **同步部署采集器配置。** 仅替换二进制不会应用 SQL 与标签修正。替换 `/etc/pg_exporter.yml` 前，请先合并本地自定义配置。
2. **检查 `pg_sub_*` 标签变化。** 新增 `datname` 会产生新时序；按需在 PromQL 连接与聚合中保留数据库身份。`pg_sub_id` 仍为 Gauge。
3. **补齐 PG10–13 的订阅权限。** 管理员须在每个用作 Exporter **主连接数据库** 的库中，对实际监控角色执行以下授权。仅在订阅所属数据库授权并不足够。它不开放 `subconninfo`；PG14+ 在标准目录 ACL 下无需额外授权。

   ```sql
   GRANT SELECT (oid) ON pg_catalog.pg_subscription TO monitor;
   ```

4. **检查接收器状态告警。** `streaming=0`、`stopping=4`、`connecting=5`（PG19+）、`starting=6`、`waiting=7`、`restarting=8`、`stopped=9`，未知／NULL 为 `-1`，编码 1–3 保留。没有接收器行时仍不输出样本。
5. **修正过去被容忍的非法输入。** 错误 URL 转义、空 URL 文件、非有限时间值与不可达指标路径现在会校验失败。为兼容两种 HTTP mux，建议使用 `/metrics`。

未指定 `sslmode` 时仍默认 `disable`，远程连接需显式配置 TLS；scratch 容器验证证书时仍须挂载 CA。空 YAML 重载仍会替换为零个配置采集器，目录中的非法文件可能被跳过，`SIGTERM` 也不会等待活跃 HTTP 请求结束。完整运行约定见[安全指南](/zh/security/)、[HTTP API](/zh/api/)与[内置采集器](/zh/collectors/)。

## 验证范围

发布前验证覆盖竞态测试、新旧 HTTP mux、静态分析、模块与生成配置一致性、约 60.4 万次短时模糊测试，以及六个目标平台构建。非超级用户默认采集通过 PostgreSQL 9.1–9.6、10–18、19 RC1 和 PgBouncer 1.26.1 实测。运行场景包括冲突数据库别名、特殊库名、Schema／扩展变化、失败重载、断连恢复、物理备库晋升与并发 HTTP 请求；另验证了 RPM／DEB 安装与 Docker 构建。

这些检查只覆盖记录中的版本与场景，不等于所有扩展组合和生产负载均已验证。Composite、Patroni、pgBackRest 与 PostgreSQL 日志组件仍属开发工作，不包含在 v1.5.0 中。
