PG Exporter v1.6.1 is a compatible maintenance release that upgrades the build toolchain to **Go 1.27.4**, isolates duplicate-label collector rows from breaking an entire `/metrics` scrape, closes removed child-database pools on auto-discovery updates and configuration reloads, fixes hostless PostgreSQL URI normalization, and resolves several collector SQL edge cases. The PostgreSQL driver remains **lib/pq 1.12.3**, and no metric names, label keys, types, buckets, CLI flags, or HTTP routes change.

## Changes {#changes}

- **Duplicate-label collector isolation:** `parseMetricResult` now checks duplicate `(metric_family, label_values)` tuples across scalar and snapshot-histogram columns before committing samples to the collector result. A custom or misbehaving query returning duplicate label sets marks only that collector failed instead of causing `prometheus/client_golang` to abort the entire `/metrics` response.
- **Child-database pool lifecycle:** when auto-discovery removes a dropped or newly excluded database, or when `Reload()` rebuilds child targets, removed `*sql.DB` pools are explicitly closed instead of remaining open. `Exporter.Close()` also closes discovered child pools, and `Reload()` guards its lifecycle lock cleanly.
- **PostgreSQL URI normalization and redaction:** `ProcessPGURL` and `ShadowPGURL` preserve the `//` authority prefix on hostless, userless, pathless URIs such as `postgresql://?host=/tmp` instead of serializing `postgresql:?...`, which `lib/pq` rejects. `ReplaceDatname` strips `service=` alongside `dbname=` and `database=` when building discovered child DSNs, and `ShadowPGURL` redacts `sslpassword` in addition to `password`.
- **Partitioned-table and relation SQL fixes:** `pg_table` (`0700-pg_table.yml`) reports `age = 0` for partitioned parent tables (`relkind = 'p'`) instead of `2147483647` (`age(relfrozenxid)` on `relfrozenxid = 0`) and coalesces partitioned parent rollup sums to `0` when no child partitions exist. `pg_table_size` (`0810-pg_table_size.yml`) excludes temporary schemas (`pg_temp*`) alongside system and TOAST schemas so scrapes skip transient session temp tables.
- **Duration clamping and identifier quoting:** `pg_activity` (`0410-pg_activity.yml`) clamps `max_duration`, `max_tx_duration`, and `max_conn_duration` with `greatest(..., 0)` to prevent negative sub-millisecond durations. The optional `pg_tsdb_hypertable` collector (`1800-pg_tsdb_hypertable.yml`) quotes `hypertable_schema` and `hypertable_name` with `format('%I.%I', ...)::regclass` for mixed-case or special-character identifiers. The v1.6.1 source tag also includes the `282e19d` legacy `pg_table_size` fix for historical PostgreSQL 9.1–9.6 environments.
- **Packaging, systemd, and standalone Docker builds:** `package/pg_exporter.service` adds `ExecReload=/bin/kill -HUP $MAINPID` for `systemctl reload pg_exporter` and points `Documentation=` to `https://exp.pgsty.com/docs/`. Standalone `Dockerfile` builds now inject `Version`, `Branch`, `Revision`, and `BuildDate` ldflags on **Go 1.27.4**, matching GoReleaser archives and packages. Residual local design drafts under `docs/design/` are removed from the source repository in favor of the companion [Design archive](/design/).

## Upgrade notes {#metric-compatibility}

1. **Deploy both the binary and collector YAML.** Package upgrades preserve existing `/etc/pg_exporter.yml` and `/etc/default/pg_exporter` files; merge the updated `pg_exporter.yml` (or split `config/*.yml` files) to pick up the `pg_table`, `pg_table_size`, `pg_activity`, and `pg_tsdb_hypertable` SQL fixes. The default bundle retains 58 YAML files, 96 branches, 59 namespaces, and 460 distinct metric definitions.
2. **Review freeze-age workarounds on partitioned tables.** If alert rules previously filtered out `pg_table_age == 2147483647` on partitioned parents, those workarounds remain harmless and partitioned parents now emit `0` directly.
3. **Use `systemctl reload` when desired.** Updating the packaged systemd unit enables `sudo systemctl reload pg_exporter` (`SIGHUP`) in addition to `POST /reload`.

When upgrading from v1.5.0 or earlier, review the [v1.6.0 release notes](/release/v1.6.0/) for independent health probes, scrape concurrency budgets, and cross-database progress OID labels, as well as the [v1.5.0 migration notes](/release/v1.5.0/) for subscription labels, receiver states, and PostgreSQL 10–13 grants. See [compatibility](/compatibility/#exporter-161-metrics) for the full summary table.

## Verification scope {#verification-scope}

Release validation at tag `v1.6.1` (`d0dead1`) passed `go mod tidy -diff`, `make conf conf9` idempotency checks, the full race detector test suite (`go test -race -count=1 ./...`), Go 1.21 HTTP mux compatibility tests (`GODEBUG=httpmuxgo121=1`), `go vet ./...`, six-target cross-compilation, and RPM/DEB package and SHA-256 checksum checks in GitHub Actions (`CI` and `Release`). New unit regressions cover duplicate scalar/histogram label isolation, child-pool closure on database removal and reload, hostless URI authority preservation, `service=` stripping, `sslpassword` redaction, `int`/`uint` column conversion, and collector SQL invariants.

Post-release verification confirmed all 12 GitHub Release artifacts and `checksums.txt`, verified the published Darwin arm64 archive binary (`pg_exporter v1.6.1`, `go1.27.4`), inspected the published Docker Hub `pgsty/pg_exporter:1.6.1` and `pgsty/pg_exporter:latest` multi-arch OCI manifests (`linux/amd64` and `linux/arm64`, `sha256:26d730f2ea906e7597cd5cfd196ecebeb935a77e5a1273301bac1b7970a06361`), and ran `.github/scripts/test-image.sh` against the pulled registry image (CA bundle, license, default configuration, and TLS verification checks). Live multi-database scraping (18 databases, 38 active collectors on `postgres`, zero query errors) and `SIGHUP` reload were verified on Darwin arm64 against PostgreSQL 18.6. Broad cross-version server acceptance inherits the v1.6.0 baseline; Composite, Patroni, pgBackRest, and PostgreSQL-log components remain on the separate `snort` development branch and are not included in v1.6.1.
