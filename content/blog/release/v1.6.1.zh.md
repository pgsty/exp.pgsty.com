PG Exporter v1.6.1 是一次向后兼容的维护版本：升级构建工具链至 **Go 1.27.4**，隔离返回重复标签集的单个采集器以避免中断整次 `/metrics` 抓取，在自动发现移除子库及配置重载时关闭失效的子库连接池，修复无主机名 PostgreSQL URI 的规范化序列化，并修正多项采集器 SQL 边界问题。PostgreSQL 驱动保持 **lib/pq 1.12.3**，所有指标名称、标签键、指标类型、直方图分桶、命令行参数与 HTTP 路由均保持不变。

## 修复与改进 {#changes}

- **重复标签采集器隔离：** `parseMetricResult` 在写入采集结果前预先校验标量与快照直方图列的 `(metric_family, label_values)` 唯一性。当自定义查询或异常数据返回重复标签组合时，仅将该采集器标记为失败，不再触发 `prometheus/client_golang` 中断整次 `/metrics` HTTP 响应。
- **子库连接池生命周期回收：** 当自动发现刷新移除已删除或新排除的数据库，或 `Reload()` 重建子目标实例时，显式关闭被移除的 `*sql.DB` 连接池以消除连接泄漏；`Exporter.Close()` 同步关闭已发现的子库连接池，`Reload()` 修正生命周期锁保护。
- **PostgreSQL URI 规范化与脱敏：** `ProcessPGURL` 与 `ShadowPGURL` 在序列化无主机、无用户、无路径的 URI（如 `postgresql://?host=/tmp`）时保留 `//` 权威前缀，避免生成被 `lib/pq` 拒绝的 `postgresql:?...`；`ReplaceDatname` 为自动发现子库重写连接串时在 `dbname=`、`database=` 之外同步剥离冲突的 `service=` 参数；`ShadowPGURL` 在 `password` 之外补充脱敏 `sslpassword`。
- **分区表、无索引表与临时关系 SQL 修复：** `pg_table`（`0700-pg_table.yml`）对 `c.relfrozenxid = '0'::xid`（如分区父表 `relkind = 'p'`）直接输出 `age = 0`，避免计算出 `2147483647`（`INT32_MAX`）；为 `tbl_scan`、`tup_read` 与 `n_tup_mod` 的加法表达式补充 `COALESCE(..., 0)`，修复无索引表（`idx_scan IS NULL`）或缺少 `pg_stat_user_tables` 统计行的对象因 `seq_scan + NULL` 退化为 `0` 的问题；并为 `pg_table_10`（`PG 9.4–12`）的 `n_live_tup`、`n_dead_tup`、`n_mod_since_analyze` 补齐 `default: 0` 以对齐 `PG 13+`。`pg_table_size`（`0810-pg_table_size.yml`）在系统目录与 TOAST 模式之外排除临时模式（`pg_temp*`），避免抓取时访问其他会话的瞬态临时表。
- **耗时截断与标识符安全引用：** `pg_activity`（`0410-pg_activity.yml`）通过 `greatest(..., 0)` 截断 `max_duration`、`max_tx_duration` 与 `max_conn_duration`，消除亚毫秒级负数耗时；默认禁用的 `pg_tsdb_hypertable`（`1800-pg_tsdb_hypertable.yml`）改用 `format('%I.%I', ...)::regclass` 安全引用包含大写字母或特殊字符的模式名与超表名。v1.6.1 源码标签同时纳入 `282e19d` 针对历史遗留 PostgreSQL 9.1–9.6 的 `legacy/` 无 TOAST 表大小修复。
- **软件包、systemd 与独立 Docker 构建：** `package/pg_exporter.service` 新增 `ExecReload=/bin/kill -HUP $MAINPID` 以原生支持 `systemctl reload pg_exporter`，并将 `Documentation=` 更新为 `https://exp.pgsty.com/docs/`。独立 `Dockerfile` 升级至 **Go 1.27.4** 并注入 `Version`、`Branch`、`Revision`、`BuildDate` 构建元数据，与 GoReleaser 发布制品保持一致；源码树内残留的 `docs/design/` 历史草稿已清理并统一归口至本站[设计归档](/zh/design/)。

## 升级注意事项 {#metric-compatibility}

1. **同时升级二进制与采集器配置。** 软件包升级默认保留本地 `/etc/pg_exporter.yml` 与 `/etc/default/pg_exporter`；请合并新版 `pg_exporter.yml`（或拆分 `config/*.yml`）以获取 `pg_table`、`pg_table_size`、`pg_activity` 与 `pg_tsdb_hypertable` 的 SQL 修复。默认配置包仍包含 58 个 YAML 文件、96 个分支、59 个命名空间与 460 个去重指标定义。
2. **检查分区表冻结年龄告警。** 若此前告警规则专门排除了分区父表的 `pg_table_age == 2147483647`，原有过滤条件依然兼容，且分区父表现在会直接输出 `0`。
3. **按需使用 `systemctl reload`。** 更新软件包附带的 systemd 服务单元后，除 `POST /reload` 外也可直接执行 `sudo systemctl reload pg_exporter`（发送 `SIGHUP`）平滑重载采集配置。

若从 v1.5.0 或更早版本跨版本升级，请同时查阅 [v1.6.0 发布说明](/zh/release/v1.6.0/)（独立健康探测、抓取并发预算与跨库进度 OID 标签）以及 [v1.5.0 迁移说明](/zh/release/v1.5.0/)（订阅标签、接收器状态映射与 PostgreSQL 10–13 监控授权）。完整变更对照表见[指标兼容性](/zh/compatibility/#exporter-161-metrics)。

## 验证范围 {#verification-scope}

`v1.6.1` 标签（`d0dead1`）在本地与 GitHub Actions（`CI` 与 `Release` 工作流）通过了 `go mod tidy -diff`、`make conf conf9` 幂等检查、完整 race 并发检测测试（`go test -race -count=1 ./...`）、Go 1.21 HTTP mux 兼容测试（`GODEBUG=httpmuxgo121=1`）、`go vet ./...`、六目标平台交叉编译，以及 RPM／DEB 软件包与 SHA-256 校验和验证。新增回归单测覆盖标量／直方图重复标签隔离、子库移除与重载时的连接池关闭、无主机 URI 权威前缀保留、`service=` 剥离、`sslpassword` 脱敏、`int`／`uint` 列转换及采集器 SQL 结构不变量。

发布后验收核对了 GitHub Release 全部 12 个平台制品与 `checksums.txt`，验证了 Docker Hub 公开多架构镜像 `pgsty/pg_exporter:1.6.1` 与 `pgsty/pg_exporter:latest`（`linux/amd64` + `linux/arm64`，`sha256:26d730f2ea906e7597cd5cfd196ecebeb935a77e5a1273301bac1b7970a06361`）的 `.github/scripts/test-image.sh` 镜像自检与流复制主库抓取，并在 Debian 12 与 Rocky Linux 9 容器中实测了公开 DEB／RPM 软件包的安装、配置校验与 systemd 单元。基于公开发布的 v1.6.1 制品，以非超级用户 `monitor` 完成了跨版本实机矩阵验收且全部零查询报错：覆盖 **PostgreSQL 10–18 与 19 RC1** 主库（多库自动发现、`DROP DATABASE` + `/reload` 连接池回收、`SIGHUP` 热重载、`pg_stat_statements`、无索引表、无 TOAST 表、分区表、并发会话 `pg_temp*` 临时表与活跃事务）、**PostgreSQL 18 与 19 RC1** 物理流复制备库（`/replica`、`pg_recv_*`、`pg_recovery_*` 及 PG19 `pg_recovery_state_*`）、**PgBouncer 1.26.1**，以及搭配 `legacy/pg_exporter.yml` 的 **PostgreSQL 9.1–9.6**（历史遗留配置零 SQL 报错，未向后移植主干 `pg_temp*` 过滤与 `pg_table` `COALESCE` 细化）。Composite、Patroni、pgBackRest 与 PostgreSQL 日志组件仍在独立的 `snort` 开发分支上，不包含在 v1.6.1 中。
