{{ if $zh }}你得自己走完这些{{ else }}Everything is on you{{ end }}

  • {{ if $zh }}下一台机器、下一次 PG 大版本升级，整套再来一遍{{ else }}Do it again on the next host, and again after the next PG major upgrade{{ end }}

01 · {{ if $zh }}扩展目录{{ else }}THE CATALOG{{ end }}

◇ {{ if $zh }}不用猜包名，不用对版本{{ else }}No package-name guessing. No version matching{{ end }}

  • {{ if $zh }}pig ext list duck 按名字、分类、PG 版本检索目录，pig ext info 看详情{{ else }}pig ext list duck searches the catalog by name, category, and PG version; pig ext info shows the detail{{ end }}
  • {{ if $zh }}扩展名与包名都认：pig install vector 与 pgvector 等价{{ else }}Extension name or package name, both work: pig install vector equals pgvector{{ end }}
  • {{ if $zh }}pig ext scan -v 18 扫出这台机器上装了什么、缺了什么{{ else }}pig ext scan -v 18 reports what is actually installed on this host, and what is missing{{ end }}
  • {{ if $zh }}目录随二进制一起分发，也可以 pig ext reload 单独刷新{{ else }}The catalog ships inside the binary, and pig ext reload refreshes it on its own{{ end }}

{{ if $zh }}扩展从「找得到、编得出」变成「装得上」{{ else }}Extensions stop being a build problem and become an install{{ end }}

find-and-install.sh 
# search the catalog

# install for a given PG major

# what is on this host?
pig ext status -v 18
